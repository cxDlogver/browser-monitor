# 01 · 平台接入与数据链路全景（从创建项目到看板出图）

> 面向**第一次接触本项目**的开发者。本文按实际操作顺序，把「注册 → 创建项目 → 拿到 DSN → 业务侧接入 SDK → SDK 上报 → 平台落库 → 异步投影 → 看板查询」整条链路讲清楚，每一步都给出**代码所在文件**（代码块首行标注路径），并说明**数据库里会写入什么、结构长什么样**。
>
> 阅读顺序建议：先看第 1 节的十步全景图，再按自己负责的环节跳到对应章节。

---

## 1. 三个包各自负责什么

本仓库是 monorepo，`browser-monitor/` 下有三个包：

| 包 | 目录 | 职责 |
| --- | --- | --- |
| **protocol** | `browser-monitor/protocol/` | 唯一的「线上协议」：zod schema + 类型 + 常量（如 `PROTOCOL_VERSION = '2.0'`）。SDK 与平台共用，避免两边各写一份 DTO |
| **sdk** | `browser-monitor/sdk/` | 运行在用户浏览器里的采集端，把数据加工成协议事件并上报 |
| **platform** | `browser-monitor/platform/` | 服务端：`apps/api`（接收与查询）、`apps/worker`（异步投影）、`apps/web`（控制台 UI）、`packages/database`（迁移与连接池）、`packages/shared`（隐私/阈值/配置） |

一句话：**SDK 只生产协议事件，平台只消费协议事件，协议由 protocol 包定死。**

## 2. 十步全景图

```text
① 注册/登录                POST /api/v1/auth/register → /login → 拿到会话 Cookie
        ↓
② 创建项目                 POST /api/v1/projects  { displayName, appName }

        ↓
⑤ 用户访问页面，SDK 采集    Instrumentation → Signal → Collector → Processing → Transport
        ↓
⑥ HTTP 上报                POST /api/v2/ingest/<publicKey>/envelopes

        ↓
⑦ 平台接收并落库           resolveProject(key) → 校验 origin/限流/逐条事件 → INSERT telemetry_events
```

登录后服务端下发 `bm_session` Cookie，后续所有 `/api/v1/**` 请求都经过 `SessionGuard + CsrfGuard`：

两个输入项的含义完全不同，这是整个接入过程**最容易踩的坑**：

| 字段 | 作用 | 约束 | 谁在用 |
| --- | --- | --- | --- |
| `displayName`（项目名称） | 只是给人看的展示名 | 1–120 字符 | 控制台列表、邮件 |
| `appName`（SDK app.name） | **业务代码里 `app.name` 必须和它完全一致**，否则上报会被逐条拒绝 | 只允许 `a-zA-Z0-9._-` | 服务端逐条校验 `app_name_mismatch` |

### 4.3 落库：一个事务写五张表

```ts
// browser-monitor/platform/apps/api/src/projects/projects.service.ts（第 58–102 行，节选）
async create(userId: string, displayName: string, appName: string) {
  const publicKey = createOpaqueToken('bm_pk_');          // ← 生成写入公钥
  const userHashSalt = createOpaqueToken();               // ← 用户 ID 哈希用的盐
  const defaultOrigin = new URL(this.config.PUBLIC_BASE_URL).origin;
  const client = await this.database.pool.connect();
  try {
    await client.query('BEGIN');
    const project = await client.query<{ id: string }>(
      `INSERT INTO projects(display_name, app_name, user_hash_salt)
       VALUES ($1, $2, $3) RETURNING id`,
      [displayName.trim(), appName.trim(), userHashSalt],
    );
    const projectId = project.rows[0]!.id;
    await client.query(
      `INSERT INTO project_members(project_id, user_id, role) VALUES ($1, $2, 'owner')`,
      [projectId, userId],
    );
    await client.query(
      `INSERT INTO ingestion_keys(project_id, public_key, label) VALUES ($1, $2, 'default')`,
      [projectId, publicKey],
    );
    await client.query(
      `INSERT INTO allowed_origins(project_id, origin) VALUES ($1, $2)`,
      [projectId, defaultOrigin],
    );
    await client.query(
      `INSERT INTO audit_logs(project_id, actor_user_id, action, detail)
       VALUES ($1, $2, 'project.created', jsonb_build_object('appName', $3::text))`,
      [projectId, userId, appName.trim()],
    );
    await client.query('COMMIT');
    return { id: projectId, displayName, appName, role: 'owner' as const, dsn: this.toDsn(publicKey) };
  } catch (error) { await client.query('ROLLBACK'); throw error; } finally { client.release(); }
}
```

### 4.4 落到数据库里的结构

```sql
-- browser-monitor/platform/packages/database/migrations/0001_platform.sql（第 37–75 行）
CREATE TABLE projects (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  display_name varchar(120) NOT NULL,      -- 项目名称（展示用）
  app_name varchar(128) NOT NULL,          -- SDK app.name（强校验用）
  user_hash_salt varchar(128) NOT NULL,    -- 用户 ID 哈希盐（每项目不同）
  enabled boolean NOT NULL DEFAULT true,   -- false 时上报直接 404
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE project_members (            -- 项目成员与角色 owner/member
  project_id uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  user_id uuid NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role varchar(16) NOT NULL CHECK (role IN ('owner', 'member')),
  created_at timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (project_id, user_id)
);

CREATE TABLE ingestion_keys (             -- 写入公钥：上报 URL 里的那一段
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  project_id uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  public_key varchar(96) NOT NULL UNIQUE,  -- 形如 bm_pk_xxxxxxxx
  label varchar(80) NOT NULL DEFAULT 'default',
  active boolean NOT NULL DEFAULT true,
  expires_at timestamptz,                 -- 轮换时旧 key 会设 24h 后过期
  last_used_at timestamptz,               -- 每次成功上报会更新
  created_at timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE allowed_origins (            -- 来源白名单，不在列表里 → 403
  project_id uuid NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  origin varchar(512) NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  UNIQUE (project_id, origin)
);
```

创建完成后，数据库里大致是这样（示例值）：

```text
projects          { id: 3f1c…, display_name: '客户中心', app_name: 'customer-center', user_hash_salt: 'a9f…', enabled: true }
project_members   { project_id: 3f1c…, user_id: 7b2e…, role: 'owner' }
ingestion_keys    { project_id: 3f1c…, public_key: 'bm_pk_9Kd2Lm…', label: 'default', active: true, expires_at: null }
allowed_origins   { project_id: 3f1c…, origin: 'https://monitor.example.com' }   ← 默认只有平台自己的域名
audit_logs        { project_id: 3f1c…, action: 'project.created', detail: { appName: 'customer-center' } }
```

**⚠️ 注意最后一行**：默认白名单只有 `PUBLIC_BASE_URL` 的 origin，**业务域名必须手动添加**（见 4.6），否则浏览器上报会被 403。

## 6. 第 ④ 步：业务侧接入 SDK

```ts
// 业务应用入口（例如 src/main.ts 或 index.ts）
import { createMonitor } from '@browser-monitor/sdk';

const monitor = createMonitor({
  app: {
    name: 'customer-center',        // ★ 必须与创建项目时填写的 appName 完全一致
    version: '2.3.1',               // 应用版本，用于按版本对比
    environment: 'production',      // 环境，用于区分 prod/staging
  },
  view: {
    // 把 /orders/123 归并为路由名 /orders/:id，否则路由维度会被 ID 打散
    resolveRouteName: ({ pathname }) =>
      pathname.replace(/\/\d+/g, '/:id'),
  },
  transport: {
    dsn: 'https://monitor.example.com/api/v2/ingest/bm_pk_9Kd2Lm/envelopes',
  },
});

monitor.setUser({ id: 'u-10086', properties: { vip: 'gold' } });  // 可选：用户身份
monitor.start();

// 业务埋点（可选）
monitor.track('checkout.submit', { orderId: 'o-88', amount: 199.9 });
```

三个关键点：

| 关键点 | 说明 |
| --- | --- |
| `app.name` | 与项目 `app_name` 不一致 → 每条事件被拒（`app_name_mismatch`） |
| `view.resolveRouteName` | 平台侧所有维度都带 `route_name`，不做归并会让路由页无法聚合 |
| `transport.dsn` | 就是第 ③ 步复制的那串地址；它不是「配置项」，而是**项目身份** |

## 7. 第 ⑤ 步：SDK 侧做了什么（简述）

```text

→ MonitorPipeline 补齐上下文 → Processing 七关（校验/脱敏/去重/采样/限流）

```

详见 SDK 侧文档：`browser-monitor/sdk/docs/02~06`。本文只关心它的输出 —— **一批符合协议的事件**。

```ts
async send(batch: readonly TelemetryEnvelope[], preferBeacon: boolean): Promise<SendResult> {
  const body = JSON.stringify({
    protocolVersion: PROTOCOL_VERSION,
```

协议由 protocol 包定义（`.strict()` = 多一个字段就拒绝）：

```ts
// browser-monitor/protocol/src/schemas.ts（第 210–264 行，节选）
export const telemetryEventV2Schema = z.object({
  protocolVersion: z.literal(PROTOCOL_VERSION),
  eventId: identifier,
  type: z.enum(['performance', 'view', 'event']),
  name: z.string().trim().min(1).max(MAX_EVENT_NAME_LENGTH),
  occurredAt: timestamp,
  app: appContextSchema,
  context: telemetryContextSchema,
  correlation: correlationContextSchema,
  payload: telemetryPayloadSchema,
}).strict().superRefine((event, context) => {
  if (event.type !== event.payload.type) { /* event.type must match payload.type */ }
  if (event.name !== event.payload.name) { /* event.name must match payload.name */ }
  if (event.payload.type === 'view' && event.context.viewId !== event.payload.viewId) { /* 一致性校验 */ }
});

export const telemetryBatchHeaderV2Schema = z.object({
  protocolVersion: z.literal(PROTOCOL_VERSION),
  sentAt: timestamp,
  sdk: z.object({ name: z.string().trim().min(1).max(128), version: z.string().trim().min(1).max(64) }).strict(),
  events: z.array(z.unknown()).min(1).max(MAX_BATCH_EVENTS),
}).strict();
```

注意批次头只校验 `events` 是数组，不逐条校验 —— 这是**Partial Acceptance** 设计：单条坏事件不会让整批失败。

### 9.2 校验顺序（每一步失败都会直接返回，不写库）

```text
① 协议版本         ≠ 2.0                      → 422 unsupported_protocol
② 批次头结构       zod 失败                   → 422 invalid_batch
③ publicKey → 项目 查不到/停用/禁用/过期      → 404 invalid_ingestion_key
④ Origin 白名单    不在列表 / 缺失            → 403 origin_not_allowed / origin_required
⑤ 限流            项目+IP 超额               → 429 ingestion_rate_limited
⑥ 逐条事件        schema 失败                → invalid_event（仅该条）
                  app.name ≠ 项目 app_name    → app_name_mismatch（仅该条）
                  occurredAt 超出时间窗口     → event_time_out_of_range（仅该条）
```

**公钥解析（最关键的一步）**：

```ts
// browser-monitor/platform/apps/api/src/ingestion/ingestion.service.ts（第 263–275 行）
private async resolveProject(publicKey: string): Promise<IngestionProject> {
  const result = await this.database.pool.query<IngestionProject>(
    `SELECT p.id AS project_id, p.app_name, p.user_hash_salt
     FROM ingestion_keys k JOIN projects p ON p.id = k.project_id
     WHERE k.public_key = $1 AND k.active AND p.enabled
       AND (k.expires_at IS NULL OR k.expires_at > now())`,
    [publicKey],
  );
  const project = result.rows[0];
  if (!project) throw new NotFoundException({ code: "invalid_ingestion_key" });
  return project;
}
```

**所以：项目没创建 → 没有 key → 404 → 一条数据都不会落库**（事务根本没开始）。

**来源校验**：

```ts
// browser-monitor/platform/apps/api/src/ingestion/ingestion.service.ts（第 277–297 行）
private async assertOrigin(projectId: string, origin: string | undefined): Promise<void> {
  if (!origin) {
    if (this.config.ALLOW_ORIGINLESS_INGEST) return;
    throw new ForbiddenException({ code: "origin_required" });
  }
  let normalized: string;
  try { normalized = new URL(origin).origin; }
  catch { throw new ForbiddenException({ code: "origin_not_allowed" }); }
  const result = await this.database.pool.query(
    "SELECT 1 FROM allowed_origins WHERE project_id = $1 AND origin = $2",
    [projectId, normalized],
  );
  if (result.rowCount !== 1) throw new ForbiddenException({ code: "origin_not_allowed" });
}
```

### 9.3 写入：一个事务落两张表

```ts
// browser-monitor/platform/apps/api/src/ingestion/ingestion.service.ts（第 148–217 行，节选）
await client.query("BEGIN");
// ① 对 eventId 取事务级咨询锁，保证并发批次不死锁（Timescale 唯一索引需含分区键）
await client.query(
  `SELECT pg_advisory_xact_lock(hashtextextended($1 || ':' || ids.event_id, 0))
   FROM unnest($2::text[]) AS ids(event_id) ORDER BY ids.event_id`,
  [`ingest:${project.project_id}`, eventIds],
);
// ② 查已存在的 eventId → 幂等去重
const existing = await client.query(
  `SELECT event_id FROM telemetry_events WHERE project_id = $1 AND event_id = ANY($2::text[]) GROUP BY event_id`,
  [project.project_id, eventIds],
);
// ③ INSERT ... ON CONFLICT DO NOTHING，并把真正插入的行写入 outbox_tasks
const inserted = await client.query(
  `WITH input AS (SELECT * FROM jsonb_to_recordset($2::jsonb) AS row(...)),
   inserted_events AS (
     INSERT INTO telemetry_events(project_id, event_id, occurred_at, type, name, environment,
       app_version, session_id, view_id, route_name, user_hash, event)
     SELECT $1, ... FROM input ON CONFLICT DO NOTHING
     RETURNING event_id, occurred_at, event
   )
   INSERT INTO outbox_tasks(project_id, event_id, occurred_at, event)
   SELECT $1, event_id, occurred_at, event FROM inserted_events
   RETURNING event_id`,
  [project.project_id, JSON.stringify(rows)],
);
// ④ 更新 key 的最近使用时间
await client.query("UPDATE ingestion_keys SET last_used_at = now() WHERE public_key = $1", [publicKey]);
await client.query("COMMIT");
```

## 10. 第 ⑧ 步：Worker 把事件投影成可查询的样本

### 10.1 领取任务（抢占式，可多实例并行）

```ts
// browser-monitor/platform/apps/worker/src/outbox-worker.ts（第 69–89 行，节选）
const result = await this.database.pool.query<OutboxTask>(
  `WITH candidates AS (
     SELECT id FROM outbox_tasks
     WHERE (status = 'pending' AND available_at <= now())
        OR (status = 'processing' AND locked_at < now() - INTERVAL '5 minutes')
     ORDER BY available_at, created_at
     LIMIT $1
     FOR UPDATE SKIP LOCKED
   )
   UPDATE outbox_tasks o SET
     status = 'processing', locked_at = now(), locked_by = $2, attempts = attempts + 1
   FROM candidates c WHERE o.id = c.id
   RETURNING o.id, o.project_id, o.event_id, o.event, o.attempts`,
  [this.config.WORKER_BATCH_SIZE, this.workerId],
);
```

`FOR UPDATE SKIP LOCKED` 让多个 Worker 互不阻塞；处理超过 5 分钟的任务会被重新领取。

```sql

CREATE MATERIALIZED VIEW performance_rollup_1h
WITH (timescaledb.continuous) AS
SELECT
  time_bucket(INTERVAL '1 hour', bucket) AS bucket,
  project_id, name, environment, app_version, route_name, threshold_version_id,
  sum(sample_count)::bigint AS sample_count,
  min(minimum) AS minimum, max(maximum) AS maximum,
  sum(average * sample_count) / NULLIF(sum(sample_count), 0) AS average,
  rollup(value_percentiles) AS value_percentiles,       -- 分位数可再聚合
```

## 13. 排错速查表

| 现象 | HTTP | 原因 | 处理 |
| --- | --- | --- | --- |
| 一条数据都没有 | 404 `invalid_ingestion_key` | 项目未创建 / key 停用 / 项目禁用 / key 已过期 | 创建项目或重新复制 DSN |
| 一条数据都没有 | 403 `origin_not_allowed` | 业务域名不在 `allowed_origins` | 设置页添加 origin |
| 整批失败 | 422 `unsupported_protocol` | SDK 与平台协议版本不一致 | 升级 SDK 或平台 |
| 整批失败 | 422 `invalid_batch` | 批次头缺字段 / 多了字段（`.strict()`） | 检查是否自定义了上报体 |
| 部分被拒 | `app_name_mismatch` | 业务 `app.name` ≠ 项目 `app_name` | 改成一致 |
| 部分被拒 | `event_time_out_of_range` | 客户端时间偏差过大 | 校准用户机器时间 |
| 部分被拒 | `invalid_event` | 单条事件不合 schema | 看 `rejections[].index` 定位 |
| 间歇失败 | 429 | 项目 + IP 维度限流 | 降低上报量或调整限流 |
| 数据已 accepted 但看板没有 | — | Worker 未运行 / 任务在死信 | 看 `outbox_tasks` 与 `dead_letter_tasks` |

**SDK 侧要特别注意**：非 2xx/408/429/5xx 的响应（如 404/403）被判定为 `retryable: false`，**不会重试**；而当前 `drain` 失败时不会把这一批放回队列 —— 这批数据会真正丢失。所以务必**先建项目、配好白名单，再上线 SDK**。

## 14. 一图流总结（步骤 → 代码位置 → 数据变化）

| 步骤 | 代码位置 | 数据库变化 |
| --- | --- | --- |
| 注册/登录 | `apps/api/src/auth/auth.controller.ts` | `users` / `user_sessions` |
| 创建项目 | `apps/api/src/projects/projects.service.ts` → `create()` | `projects` + `project_members` + `ingestion_keys` + `allowed_origins` + `audit_logs` |
| 拿 DSN | `projects.service.ts` → `toDsn()` | — |
| 添加来源 | `PUT /api/v1/projects/:id/origins` | `allowed_origins` 全量替换 |
| 业务接入 | 业务代码 `createMonitor({ transport: { dsn } })` | — |
| SDK 上报 | `sdk/src/transport/sender/index.ts` | 无（HTTP 请求） |
| 接收校验 | `apps/api/src/ingestion/ingestion.service.ts` | 校验失败则不写库 |
| 落库 | 同上（事务） | `telemetry_events` + `outbox_tasks` |
| 异步投影 | `apps/worker/src/processor.ts` | `performance_samples` / `view_records` / `custom_event_samples` |
| 聚合 | `packages/database/migrations/0002 ~ 0003` | `*_rollup_1m` / `*_rollup_1h` |
| 查询 | `apps/api/src/analytics/analytics.controller.ts` | 读物化视图 |

**一句话**：先用 `displayName + appName` 创建一个项目，平台在同一个事务里生成 `publicKey` 并落成 DSN；业务侧把这个 DSN 和**完全相同的 `app.name`** 配进 SDK；SDK 把采集到的数据按协议 v2 批量 POST 到 `/api/v2/ingest/<key>/envelopes`；平台校验 key → origin → 限流 → 逐条事件后，事务写入 `telemetry_events` 与 `outbox_tasks`；Worker 再把事件投影成样本表，连续聚合后供看板查询。任何一环没对齐（key 不存在、origin 不在白名单、app.name 不一致），数据都会在写库之前被拒，且 SDK 不会重试。
